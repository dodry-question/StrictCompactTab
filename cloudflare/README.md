# Worker для Strict Compact Tab

Один бесплатный Worker закрывает две задачи:

1. **Облачная синхронизация настроек и ярлыков.** Данные шифруются в браузере
   (AES-GCM, ключ выводится из кода синхронизации через PBKDF2), поэтому KV
   хранит только шифротекст. Worker не знает ни код, ни содержимое.
2. **Автообновление расписания.** Worker сам читает публичную стену сообщества
   ВК, находит свежий `.xlsx`, скачивает его, считает SHA-256 и хранит копию в
   KV. Расширение обращается **только к Worker** и никогда — к `vk.com`.

VPS не нужен. Всё укладывается в бесплатный тариф Cloudflare Workers: запросов
мало, KV-записей — несколько в сутки.

## Развёртывание

Нужен аккаунт Cloudflare (бесплатный) и Node.js.

```bash
# из корня проекта
npx wrangler login
npx wrangler kv namespace create SYNC
```

Команда выведет `id = "..."`. Вставьте его в `cloudflare/wrangler.toml` вместо
`PASTE_KV_NAMESPACE_ID_HERE`. Затем:

```bash
npx wrangler deploy -c cloudflare/wrangler.toml
```

Wrangler напечатает адрес вида `https://strict-compact-tab.<ваш-поддомен>.workers.dev`.
Этот адрес вводится в расширении: **Настройки → Облачная синхронизация → Сервер**.
Там же (в общем списке настроек) есть тумблер **«Сервер расширения (Worker)»** —
по умолчанию он выключен, и пока он выключен, расширение не отправляет Worker
ни одного запроса: ни за облаком, ни за расписанием, ни за погодой, ни за
иконками. Погода при этом работает напрямую через Open-Meteo.

Проверка, что Worker жив:

```bash
curl https://strict-compact-tab.<ваш-поддомен>.workers.dev/health
# {"ok":true,"service":"strict-compact-tab"}
```

Cron-триггер (`17 */6 * * *`) начнёт работать после первого деплоя. Первый файл
можно не ждать: запрос `/schedule/latest` при пустом кеше сам сходит в VK.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | проверка Worker |
| `GET` | `/sync/<slot>` | получить шифрованный конверт |
| `PUT` | `/sync/<slot>` | записать конверт (нужен `X-Sync-Auth`) |
| `GET` | `/schedule/latest` | метаданные свежего расписания |
| `GET` | `/schedule/file` | скачать `.xlsx` из кеша |
| `GET` | `/weather/forecast?latitude=…&longitude=…` | прогноз Open-Meteo через прокси (кеш 10 минут) |
| `GET` | `/weather/geocode?name=…` | поиск координат города Open-Meteo (кеш сутки) |
| `GET` | `/favicon?domain=…&size=…` | иконка сайта с CORS (кеш неделя) |

`slot` и `X-Sync-Auth` выводятся на устройстве из кода синхронизации. Worker
хранит только SHA-256 от `X-Sync-Auth` и не даёт перезаписать слот другим
ключом.

## Что видит VK

Запросы к VK идут с IP Cloudflare, без cookies, без токена и без аккаунта.
Расширение не запрашивает у VK ничего напрямую. Пользовательский IP VK не видит.

Worker читает:

* `al_wall.php?act=get_wall&al=1&owner_id=-85060840&offset=...&type=own` —
  публичные страницы стены по 10 постов;
* при недоступности — `widget_community.php?gid=85060840&mode=4` и публичные
  embed-страницы постов.

Никакие данные пользователя в VK не отправляются.

## Погода

`/weather/*` — тонкий прокси к Open-Meteo с белым списком параметров
(`current`, `hourly`, `daily`, `forecast_days`, `timezone`, единицы) и
проверкой координат. Адрес апстрима зашит в код, поэтому прокси нельзя
использовать как открытый редирект. Ответы кешируются Cache API на 10 минут
(геокодирование — на сутки), KV не расходуется. Open-Meteo видит IP
Cloudflare, а не пользователя. Если адрес Worker в настройках не задан,
расширение ходит в Open-Meteo напрямую.

## Иконки ярлыков

`/favicon` нужен не для скорости сервера, а для CORS: Google отдаёт иконки без
заголовка `access-control-allow-origin`, поэтому страница расширения может
показать их через `<img>`, но не может прочитать байты и сохранить на
устройство. Worker забирает картинку сам и отдаёт с CORS — клиент кладёт её в
`localStorage` как `data:URL` и со следующей вкладки рисует из памяти, вообще
без сети. Обновление — не чаще раза в сутки и только в фоне: сохранённая
иконка показывается сразу, свежая дорисовывается, когда придёт.

Прокси закрытый: принимаются только голое имя хоста и размер из списка
16/32/64/128, адрес апстрима зашит в код, ответ обязан быть картинкой и не
больше 128 КБ. Кеш — Cache API на неделю, KV не расходуется. Google видит IP
Cloudflare, а не пользователя. Если рубильник выключен, иконки грузятся
напрямую через `<img>`, как раньше.

## Расписание и рубильник

Включение рубильника делает **ровно один** запрос `GET /schedule/latest?refresh=1`:
Worker один раз обходит стену ВК и кладёт файл с метаданными в KV. Дальше их
держит сервер — обычный запрос и cron (`17 */6 * * *`) обновляют кеш сами.
Повторные `refresh=1` (например, несколько человек включили рубильник подряд)
не запускают новый обход чаще раза в 5 минут: свежие метаданные отдаются из KV.

## Ограничения

* **Бесплатный тариф.** Если Cloudflare изменит лимиты, может понадобиться
  платный план; код от этого не зависит.
* **KV eventually consistent.** Запись обычно видна в течение минуты. Сразу
  после загрузки на втором устройстве может понадобиться повторить «Скачать».
* **Роль «главное устройство» — клиентская.** Любой, кто знает код, может
  вывести ключ записи. Это защита от случайной перезаписи, а не от человека,
  которому вы сами передали код. Код — это пароль: не публикуйте его.
* **Стена ВК.** Если сообщество закроет стену или сменит формат вложений,
  Worker перестанет находить файл. Расширение при этом продолжает работать с
  локально загруженным расписанием.
* **Домен.** Манифест расширения разрешает только `https://*.workers.dev`.
  При переходе на собственный домен добавьте его в `host_permissions` и
  `content_security_policy.connect-src` в `manifest.json`.
* **Локальная разработка.** `npx wrangler dev -c cloudflare/wrangler.toml`
  поднимает Worker на `http://localhost:8787`. Чтобы расширение могло к нему
  обратиться, добавьте этот адрес в манифест (в релизе его нет).

## Проверка без расширения

```bash
# метаданные (первый запрос может занять несколько секунд — идёт обход стены)
curl https://<worker>/schedule/latest

# скачать файл
curl -L https://<worker>/schedule/file -o schedule.xlsx
```

Ответ `/schedule/latest`:

## Переменные

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VK_OWNER_ID` | `-85060840` | сообщество с расписанием |
| `SCHEDULE_MAX_PAGES` | `6` | глубина обхода стены (страниц по 10 постов) |
| `SCHEDULE_TTL_SECONDS` | `3600` | когда кеш считается устаревшим |
| `SYNC_MAX_BYTES` | `2097152` | предел шифрованного конверта |
| `SCHEDULE_MAX_BYTES` | `12582912` | предел `.xlsx` |
